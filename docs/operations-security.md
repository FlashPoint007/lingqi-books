# 阅读稳定性、防滥用与后续规划

本轮优先保护接口、上游请求和 Worker 内存；没有修改站点访问范围。当前日志中的源站超时、502 和客户端取消不足以确认有 DDoS 攻击。

## 已实现的应用保护

三个公开读取接口在进入适配器之前统一检查：`/api/catalog`、`/api/reader-image`、`/api/content-image`。

| 类型 | 突发额度 | 每分钟恢复额度 | 单实例并发上限 |
| --- | ---: | ---: | ---: |
| 目录、正文、搜索 | 120 | 240 | 20 |
| 封面、插图、漫画页 | 120 | 360 | 16 |
| 检测、查找其他来源 | 12 | 36 | 6 |

普通读取或图片消耗 1 额度；联合搜索消耗 8；联合检测及不指定目标源的换源查找消耗 6；完整阅读验证消耗 3。额度按类型分开。所有类型合计最多 32 个进行中的响应。并发名额在响应流完成、取消、出错或 60 秒超时后释放，避免只限制响应头而遗漏图片传输。

在 Cloudflare 请求上下文存在时采用平台提供的 CF-Connecting-IP；不信任 X-Forwarded-For、URL 用户 ID 或 Cookie 作为限流身份。其他运行环境共用匿名桶。最多保留 4096 个桶，120 秒过期，满额时拒绝新增桶。不会持久化或打印 IP、查询标题、正文或凭据。共享出口读者可能共享额度，需根据真实误限流情况调整。

限流返回 429，繁忙返回 503，并给出 Retry-After；前端显示等待提示，不自动循环重试。只读接口不接受 POST；未知、重复、过长参数和非法序号在访问来源之前拒绝。跨站浏览器读取与图片盗链通过 Fetch Metadata、Origin 和 CORP 限制；这些是浏览器保护，不是鉴权，脚本可省略相关头。

每个来源域名最多 3 个进行中的下载、24 个排队请求，排队最多 12 秒，连接及响应体共用 15 秒期限。保留既有作品归属校验、图床允许范围、重定向限制和来源启用检查。

已完成数据的公共解析缓存最多 80 项、估算 12 MiB，单项最多 3 MiB；元数据缓存最多 180 项、估算 8 MiB，单项最多 2 MiB。容量按序列化字符串的 UTF-16 长度估算，不是精确堆内存限制。缓存不保存跨请求进行中的 Promise；带 Authorization、Cookie、X-Api-Key 或图片票据的 HTML/JSON 不进入匿名缓存。失败响应禁止浏览器缓存。

JSON 最大 4 MB、HTML 最大 3 MB、单张图片最大 15 MB。图片验证实际文件签名，不相信 JPEG 声明；验证前缀后流式转发，超出上限或来源读取失败会中断流，不会返回伪造的完整成功图片。

## 平台防护边界

以上计数和缓存位于单个 Worker 实例内，不是跨节点严格全局限制，不能承诺抵抗大规模分布式流量、带宽攻击或平台账单消耗。实例扩容或重启会重建计数。没有新增 WAF、挑战验证码、Durable Object 或原生限流绑定；现有 Sites 管理接口未提供这些配置能力。

Cloudflare 文档说明其网络提供自动 DDoS 防护，但本仓库无法验证 Sites 账户的具体规则和阈值。若取得域名所属账户的管理权限，应先核对真实入口，再在 Worker 执行前配置托管防护及分路径限流。检测和联合搜索宜采用更紧阈值；漫画图片允许较高突发。先观察再逐步执行，分别检查移动网络共享出口、正常切源和长章节阅读。不要给所有图片强制人机挑战，也不要公开源站密钥。

参考：[DDoS 防护](https://developers.cloudflare.com/ddos-protection/)、[HTTP DDoS 规则](https://developers.cloudflare.com/ddos-protection/managed-rulesets/http/)、[Workers 原生限流及一致性限制](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)。

## 下一阶段优先级

1. **稳定性与可观察性**：按来源统计成功率、首字节时间、正文/图片失败率；区分源站 429 与本站 429，建立异常告警，聚合或抽样日志。先观察正常访问基线，再调整额度。
2. **来源质量**：为目录、正文、首图建立少量定期探测；连续失败时熔断和退避，保留其他来源结果。新增源必须验证完整阅读链路，不能只凭首页可访问启用。
3. **阅读性能**：将经过验证且无账户信息的公共目录及公开漫画图片纳入短时边缘缓存；缓存键覆盖来源配置和版本，失败不缓存，私有服务不共享。保留节流模式、单章预取及读者关闭预加载的选项。
4. **数据可靠性**：完善阅读历史/书架导入校验、重复导入合并与恢复演练；跨设备同步需先设计账户、冲突处理和数据删除流程。
5. **平台纵深防护**：在平台能力可用后配置边缘 WAF、跨节点限流、用量告警和回滚演练。严格全局计数采用有状态协调服务，不能把本地 Map 宣称为全局防护。

## 验证与应急

本地以合成请求验证参数拒绝、429 恢复、身份隔离、并发取消释放、缓存淘汰、凭据隔离、图片签名与流式传输；不对生产或第三方来源实施压力测试。生产只做正常浏览、阅读和少量无效参数检查。

异常时先区分平台入口、本站繁忙、单个来源失败和图片链路；关闭故障来源或降低预加载，比反复全源检测更有效。必要时从 Sites 版本历史回滚上一正常版本。不要通过开放任意代理地址、放宽身份验证或把密钥写入前端来恢复访问。

## v38：检索退避与公开内容边缘缓存

- 单个书源的检索最多等待 12 秒；通过请求上下文传播取消信号，覆盖通用 HTML/JSON、Bangumi/MangaDex 和 Komiic 请求。联合检索继续分批返回其他源的结果。
- 连续两次连接/5xx 故障后冷却约 30 秒，恢复失败逐级增加，最高约 5 分钟；解析结构变化、验证、拒绝访问和域名变化先冷却约 5 分钟。加入至多 10% 随机抖动。上游 429 的 Retry-After 被保留并优先满足（最长 30 分钟）。冷却结束仅放行一个有期限的恢复请求，不共享该请求的 Promise。
- 有效的零搜索结果、单本作品 404、未配置服务和单本权限问题不算书源检索故障。检索冷却不会拦截已知作品的目录或正文请求；来源状态接口返回当前实例的冷却状态和预计恢复时间。这些状态仍是单实例、非持久化数据。
- 公共目录采用 Cache API 缓存已成功解析的数据 90 秒，单条最多 1.2 MB。联合检索的每个公开来源分别缓存，因此一个来源故障不会污染其他来源。搜索状态中的 cache / cachedAt 可用于区分 HIT、MISS 和数据生成时间；显式 test 检测不使用此层边缘缓存。
- 仅崩坏3和 lnovel 公开接口的图片进入 5 分钟边缘缓存，缓存分支最多读取 2 MB，主响应保持流式传输。错误、未完整下载、过大及带 Set-Cookie 的图片不存入缓存。漫画票据/访客额度图源、个人服务和账户内容不共享。
- 带 Authorization 的请求不使用此层共享缓存。公共适配器不会读取或转发浏览器 Cookie，因此平台/偏好 Cookie 不妨碍公开目录缓存；私有服务和账户图文无论是否带 Cookie 均不缓存。status、bridge-status、正文和私人图文接口不缓存。缓存键包含站点域名、策略版本、参数、公开来源启用列表、MangaDex 屏蔽配置及 Narou 开关。禁用来源后不会命中旧策略下的数据。
- 图片参数排序不影响缓存键；手动重试跳过命中并尝试更新同一个缓存条目，避免产生无限重试键。命名缓存打开和读取分别最多等待 250 ms，缓存读写失败时仍可读取来源。
- Cache API 的内容按数据中心保存，不会自动复制至所有节点，也不保证首次请求命中。浏览器仍收到 private 缓存策略；平台入口鉴权和 v37 的限流检查保留在缓存之前。

漫画柜的零结果识别已与实际页面对齐：仅在搜索区域明确声明 0 部并显示空结果说明时返回空列表；异常页面继续报告解析错误。轻之文库的本地请求目前收到普通 nginx 403，不能据此推断为人机验证，亦未尝试绕过权限或访问控制。

托管环境适配：使用 `caches.open("lingqi-public-reading-v1")`，不使用 namespaced Worker 中禁用的 `caches.default`。缓存句柄及其打开 Promise 仅在当前请求内共享，不跨 Worker 请求保存。参考 [Worker Isolation](https://developers.cloudflare.com/cloudflare-for-platforms/workers-for-platforms/reference/worker-isolation/)。

生产复测补充：本轮轻之文库公开榜单正常返回 15 部作品；漫画柜无匹配搜索正常返回 0 部并标记成功。一次正常响应不能证明来源长期稳定，仍保留超时预算与故障退避。
